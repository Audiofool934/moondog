# Demo Media

## Offline agent recording

`moondog-offline-demo.gif` records the real deterministic `npm run --silent demo` command.

The recording uses only the synthetic public demo library and does not initialize a model, music service, OAuth credential, private import, or local profile database.

Regenerate it from the repository root with VHS 0.11.0 or newer:

```bash
vhs assets/demo/moondog-offline-demo.tape
```

Verify the committed tape and GIF contract with:

```bash
npm run verify:demo-media
```

The verifier checks the exact synthetic command, expected output path, dimensions, size ceiling, and common private-path or credential markers in the tape.

The binary GIF is still a reviewable release asset and should be visually inspected after regeneration.

VHS frame timing can vary with process startup and font rendering, so regenerated GIF bytes are not expected to have a stable checksum.

## Interactive Studio tour

`moondog-studio-tour.gif` is a five-frame capture of the real `npm start` and `npm run demo:studio` surface.

Every frame comes from one in-memory profile built by passing the deterministic 52-play fictional Extended Streaming History archive through the production Spotify importer.
The sequence shows the first screen, four-year Listening Time Machine, four long-gap historical-return tracks, 15 approximate listening stretches with two multi-track releases, and one retractable direct correction.

Regenerate it from the repository root with Chrome or Chromium and ImageMagick 7 available:

```bash
npm run generate:studio-tour
```

The capture command starts only the loopback demo-only Studio, supplies private state paths that must remain unopened, disables browser background networking, and requires the Studio API to report no private read or persistent profile write before composing the GIF.
It writes five 1240-by-840 frames to a private temporary directory, checks every PNG dimension, and removes that directory after success or failure.

The media verifier parses the GIF structure without external tools, requires exactly five frames, applies size and dimension bounds, and scans the binary for common private-path, provider-identity, and credential markers.
Browser font rasterization can vary, so the GIF bytes are not pinned to one checksum and the result must still be visually inspected after regeneration.

## Synthetic Tasteprint previews

`moondog-tasteprint-demo.html` is generated by the production Tasteprint renderer from the bounded fictional profile in `src/demo/moondog-tasteprint-demo.mjs`.

`moondog-tasteprint-card-demo.html` is generated from the same profile by the production one-screen recap-card renderer.

The same page includes a fictional year-by-year Listening Arc and Listening Time Machine so the public artifact exercises both lifetime-history renderers without exposing a real listener.

The Time Machine uses fictional chronological landmarks across four retained years and carries the same bounded interpretation language as a private profile.
Its coverage note states how many retained years have landmarks and exposes the active strongest-year, avoidance, engaged-play, and listening-time rules.

Every artist, track, date, and aggregate in both artifacts is synthetic.

Regenerate the deterministic HTML from the repository root with:

```bash
npm run generate:tasteprint-demo
```

`moondog-tasteprint-preview.png` captures the complete page's `#taste-shape` section at a 1240-by-840 CSS-pixel viewport.

`moondog-time-machine-preview.png` captures the complete page's fictional `.time-capsule-panel` at the same viewport.

`moondog-listening-patterns-preview.png` captures the complete page's `#listening-patterns` section at the same viewport.

`moondog-tasteprint-card-preview.png` captures the entire recap card at the same viewport and appears later in the README beside the private-sharing boundary.

Regenerate all four previews, together with the two README terminal screenshots, with Chrome or Chromium and tmux available:

```bash
npm run generate:tasteprint-demo
npm run generate:demo-screens
```

The command loads each committed HTML file in headless Chrome at 1240 by 840 CSS pixels.
Pages that open at a section are shown inside a full-size frame, because one-shot headless screenshots render blank when the address carries a fragment.

The `#taste-shape` target applies the intended top margin and hides the browser scrollbar for the capture without adding JavaScript.

All four committed PNGs should be visually inspected at desktop size, and both HTML artifacts should be checked at a 390-pixel viewport.

The media verifier regenerates both expected HTML artifacts in memory, requires exact matches, scans them for private identifiers and external resources, and checks the Studio tour plus all four PNG signatures, dimensions, frame count, and size bounds.

Browser rasterization can vary across operating systems, so PNG bytes are not pinned to one checksum.

## Terminal screenshots

`moondog-tui-home.png` and `moondog-tui-profile.png` show the real listening room at 100 by 34 cells in the charcoal theme.
`npm run generate:demo-screens` starts Moondog in a private tmux server with a temporary home and state directory, imports the fictional 52-play history, opens the evidence behind one track, then returns to the record sleeve.
Each screen is captured with its colors and redrawn cell by cell in headless Chrome, so nothing personal, no model, and no music service is involved.
`moondog-tui-captures.json` records the capture date, dimensions, sizes, and SHA-256 values; inspect both images before committing them.
